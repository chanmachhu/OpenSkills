# AGENTS.md

Read `README.md` first: structure, skill fields, downloads and versioning, content and design rules, workflow, checklist.

Essentials:
- Content changes never touch HTML/JS/CSS. A skill = `content/skills/<id>.json` (id = file name), themes = `content/themes.json`.
- Downloadable skills: files stored **unzipped** in `content/downloads/<id>/` with `SKILL.md` at its root. For a plugin zip, keep only `skills/<name>/`. The build zips them into `downloads/<id>-<version>.zip`. Never commit `.zip`/`.skill` files.
- Versioning: any change in `content/downloads/<id>/` needs a semver bump of `version` in the skill JSON (patch = fix, minor = new ability, major = usage change). The build does not catch a missing bump.
- `contributor` = who created the skill. Never guess it; leave it out if unknown.
- Never edit `_site/`: it is generated by `node scripts/build.js`. Run that after every change; it must end without `error:`.
- No dependencies, no build tools beyond Node stdlib (20.15+), no frameworks.
- Site text: English, short (one-sentence description, ~3 yes / ~2 not really), no commands, syntax or install steps, no "(n)" counters, no raw HTML in JSON. No source → "Ask Basile" is shown.
- Design: colors only via the CSS variables (each with a dark value), fixed px font sizes per breakpoint (never `vw`), check 390px mobile and dark mode.
- Links must stay relative: the site is served under `/OpenSkills/`.
- Git: `main` is protected. Work on a new branch from an up-to-date `main`, open a PR, merge when `build` is green. Before pushing to an existing branch, check that its PR is still open (`gh pr view`).
